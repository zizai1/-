============================================================
  Binance Sentinel 配置说明（从零部署指南）
============================================================

本文件介绍如何在一台新机器上完成全部配置并跑起来。
共 8 步，按顺序执行即可。全程需要约 10-20 分钟。

项目代码在 binance-sentinel/ 子目录中，下面所有命令都在
binance-sentinel/ 目录里执行（先 cd binance-sentinel）。


------------------------------------------------------------
0. 环境要求
------------------------------------------------------------
  - Node.js 20 或更高版本（含 npm）
  - codex CLI（OpenAI 官方命令行工具，用于跑 AI agent）
  - DeepSeek 平台 API Key（https://platform.deepseek.com 申请）
  - 币安现货账户（用于 OAuth 授权绑定）
  - 建议使用 bash 环境（Windows 可用 Git Bash）

  检查命令：
    node -v
    codex --version


------------------------------------------------------------
第 1 步  安装项目依赖
------------------------------------------------------------
  在 binance-sentinel/ 目录执行：

    npm install


------------------------------------------------------------
第 2 步  配置 .env.local（模型 API Key）
------------------------------------------------------------
  在 binance-sentinel/ 目录新建 .env.local 文件（若不存在），写入：

    LLM_API_KEY=sk-你的DeepSeek密钥

  说明：
  - 这是本项目唯一必须手动填的密钥。
  - 启动脚本 scripts/codex-server.sh 会读取它，并作为
    DEEPSEEK_API_KEY 环境变量注入 codex daemon。
  - 本项目其余配置无需改任何代码。

  .env 文件（数据库地址）默认已带，无需修改：
    DATABASE_URL="file:./prisma/dev.db"


------------------------------------------------------------
第 3 步  初始化数据库（SQLite）
------------------------------------------------------------
  在 binance-sentinel/ 目录执行：

    npx prisma db push

  成功后会自动生成 prisma/dev.db（已在 .gitignore 中排除）。


------------------------------------------------------------
第 4 步  配置 codex CLI 与币安 MCP
------------------------------------------------------------
4.1 安装 codex CLI
  安装方式见官方仓库 https://github.com/openai/codex
  （npm 安装：npm install -g @openai/codex）

4.2 编辑 codex 配置文件
  文件位置（用户主目录下）：
    Linux/macOS:  ~/.codex/config.toml
    Windows:      C:\Users\你的用户名\.codex\config.toml

  需要包含以下内容（模型用 DeepSeek，MCP 用币安官方）：

    model = "deepseek-chat"
    model_provider = "deepseek"

    [model_providers.deepseek]
    name = "DeepSeek"
    base_url = "https://api.deepseek.com"
    env_key = "DEEPSEEK_API_KEY"
    wire_api = "responses"

    [mcp_servers.binance-mcp-server]
    url = "https://agent.binance.com/mcp/agentic"

    [mcp_servers.binance-mcp-server.oauth]
    client_id = "codex"
    callback_url = "http://127.0.0.1/callback/本机自动生成的路径"

    [approval_policy.granular]
    mcp_elicitations = false
    rules = false
    sandbox_approval = false
    skill_approval = false

  说明：
  - oauth 段一般在执行 codex mcp login binance-mcp-server 时
    由 codex 自动生成/更新，callback_url 的随机路径每台机器不同，
    直接保留你自己机器上生成的值即可，不要照抄别人的。
  - [approval_policy.granular] 是兜底策略（无头拒绝），本项目
    每一轮对话会传入自己的审批策略，二者互不冲突。

4.3 验证 codex 能读到配置
  执行 codex mcp list，应能看到 binance-mcp-server。


------------------------------------------------------------
第 5 步  启动 codex app-server（终端 1）
------------------------------------------------------------
  在 binance-sentinel/ 目录执行：

    npm run codex-server

  正常表现：终端保持运行不退出，监听 ws://127.0.0.1:8787。
  该进程要一直开着，不要关掉。
  （脚本会自动从 .env.local 读取 LLM_API_KEY，无需手动 export）


------------------------------------------------------------
第 6 步  启动前端（终端 2）
------------------------------------------------------------
  在 binance-sentinel/ 目录另开一个终端执行：

    npm run dev

  浏览器打开 http://localhost:3000


------------------------------------------------------------
第 7 步  绑定币安账户（OAuth）
------------------------------------------------------------
  1. 页面右上角状态灯显示「MCP 未绑定」时，点旁边的「登录」按钮
  2. 会自动打开币安授权页面，登录你的币安账号并授权
  3. 授权完成后回到页面，约 10 秒内状态灯自动变绿（MCP Online）
     （若未变绿，等下一轮 10 秒轮询即可，无需刷新页面）

  后续随时可在右上角「登出」/「登录」切换账户授权。


------------------------------------------------------------
第 8 步  验证
------------------------------------------------------------
  在对话输入框发送：

    查看我的持仓和余额

  预期表现：
  - 中间对话流式回复，展示真实账户数据
  - 右侧 Agent Timeline 出现工具调用轨迹
  - 左侧钱包总览出现圆环图与资产分布
  - 右上角状态灯为绿色 MCP Online

  再试一句：

    分析一下 BTC 当前行情

  下单/撤单类操作会弹出黄色确认卡片，人工点确认后才执行。


------------------------------------------------------------
可选配置
------------------------------------------------------------
  ORDER_MAX_USDT
    单笔订单名义价值上限（USDT），默认 1000。
    写入 .env.local 即可，例如：
      ORDER_MAX_USDT=500

  CODEX_WS_URL
    codex daemon 地址，默认 ws://127.0.0.1:8787，一般不用改。


------------------------------------------------------------
常见问题
------------------------------------------------------------
  Q: 提示「无法连接 codex app-server」
  A: 第 5 步的 npm run codex-server 没在运行，或 8787 端口被占用。

  Q: 状态灯一直「MCP 待命」，但已登录
  A: 发一条消息即可点亮。复用会话时 daemon 不重发就绪通知，
     以实际跑通一轮对话为准。

  Q: 提示「上一轮对话仍在进行中，请稍候」
  A: 上一轮 AI 还在思考或等待确认，等它结束再发下一条。

  Q: 工具调用报 -2015（授权过期）
  A: 授权过期属正常现象，对话里会自动给出重新授权链接；
     也可以直接点右上角「登录」重新绑定。

  Q: 确认卡片点击后无反应
  A: 重启 npm run dev（热重载会残留旧连接，旧连接抢答会把
     审批流程拦截掉，重启后即恢复）。

  Q: 下单被拦截提示步长不符
  A: 按 AI 提示的「取整后数量」重新说一遍即可，例如
     「改成 0.013 再卖」。这是交易所 LOT_SIZE 规则，属正常保护。


------------------------------------------------------------
安全提醒（务必阅读）
------------------------------------------------------------
  1. .env.local 已被 .gitignore 排除，不要用 git add -f 强制
     提交，也不要把真实 Key 贴到聊天记录、截图或公开仓库。
  2. 若 Key 曾完整暴露，请立即到 DeepSeek 平台后台重置（rotate）。
  3. 币安授权（OAuth token）保存在本机 codex 配置目录
     （~/.codex），同样不要外传。
  4. 本项目默认单笔上限 1000 USDT，首次实盘建议先用极小金额
     验证全流程。
  5. AI 输出不构成投资建议，下单前请自行核对参数，盈亏自负。
